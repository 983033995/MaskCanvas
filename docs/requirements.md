# MaskCanvas 产品需求 v2

更新：2026-10-22。本文描述目标行为；实现状态见迭代进度。用户本次修订：常规 Agent 交接只使用 JSON，优先实现 Agent 提议后由用户确认调整的流程。优先级高于旧 ZIP 研究与设计稿。

## 1. 产品定义

MaskCanvas 是供使用者与 Codex、WorkBuddy、Qoder 等 Agent 共用的照片精修工作台。人可以精确标注，Agent 可以提出并执行修图计划；不同入口使用同一份照片、蒙版、版本和验收结果。

产品由独立画布、编辑核心、MCP 接口、后端适配器和JSON 交接组成。Qwen Image 与 GPT Image 2.5 是候选内容生成后端，最终编辑范围由本地合成器控制。无需先购买 Photoshop，也不要求先学 ComfyUI 节点。

图稿是直接生成的 PNG，当前已有应用开发。旧 ZIP 交接效果图保留为历史，最新交接协议与确认流程以 [agent-workflow.md](agent-workflow.md) 为准。

## 2. 使用者与目标

- 日常摄影者：自然修饰人像、清理瑕疵、整理发丝、移除干扰物，保留照片质感。
- 需要改造造型的创作者：明确指定换装、发型或轮廓调整，不把改变外貌当作默认美化。
- Agent 使用者：在已有 Agent 工具中启动任务、修改区域、查看候选或接手人工标注包。

核心目标：用户能指出具体问题、约束不能改的地方，获得可检查、可回退的结果，不需要手算裁切坐标或反复拼图。

## 3. 三种模式，统一数据

| 模式 | 发起方式 | 完成路径 |
|---|---|---|
| 人工标注 | 人画选区与保护区，填写局部意图 | 本地生成，或复制 JSON 给任一 Agent；结果引用与报告以 JSON 返回 |
| 协同精修 | 人提出目标，Agent 提议问题与区域 | 人修正选区/计划；Agent 执行；人比较并接受 |
| 自主精修 | 人提供任务目标、对象、处理范围与预算 | Agent 观察、建区、生成、检查、有限重试；通过约定条件则输出新版本 |

模式切换不复制项目，不丢失标注和历史。自主执行不要求人工打开画布；需要人工时输出明确原因与当前候选。画布仍可供用户随后接管。

不内置另一套聊天模型账号体系。Agent 的分析与执行能力取决于客户端和已配置模型；无视觉能力时可以执行完整标注包，不能声称自主识别了照片问题。

## 4. 首版功能

| ID | 需求 | 完成标准 |
|---|---|---|
| R01 | 项目导入与保存 | JPEG/PNG；方向归一化；保留原文件；重开恢复区域与版本 |
| R02 | 精细选区 | 矩形、套索、画笔、橡皮；缩放、平移；按原图坐标保存全分辨率 mask |
| R03 | 保护与上下文 | 编辑 E、保护 K、模型上下文 C 独立显示；保护优先，不能静默扩大可修改范围 |
| R04 | 局部意图 | 每个区域有名称、操作、描述、参考资料；复杂或重叠编辑明确顺序 |
| R05 | Agent 创建区域 | MCP 可导入 mask、点/框选区及修订计划；自动识别可调用可用分割服务；失败可交人 |
| R06 | 双后端 | Qwen Image 与 GPT Image 2.5 接相同任务；能力和可用状态分别检测，不静默切远端 |
| R07 | 异步作业 | 提交立即得到 job ID；可查询、恢复、有限重试；只管理本项目自己的任务 |
| R08 | 候选与版本 | 生成先成为候选；可接受、拒绝、继续编辑；原图与历史版本不可覆盖 |
| R09 | 对比验收 | 原尺寸查看、分割对比、差异视图；报告保护区和选区外的变化 |
| R10 | 自主任务 | 支持明确任务目标、保护对象、处理目的地、重试上限；需人工时暂停并保留现场 |
| R11 | 数据交接 | 复制/导出/导入标注 JSON；图片独立引用；同机共享项目，跨设备需明确绑定图片 |
| R12 | 连接管理 | Codex / WorkBuddy / Qoder 接入向导；设备和模型能力独立检查；截图不冒充连接成功 |
| R13 | 隐私边界 | 分别控制图片分析与生成目的地；默认不向未授权远端提供图像资源 |
| R14 | 异常与冲突 | 保留输入与产物；版本过期时成为分支候选，不能覆盖新标注 |

“强度”、seed、参考图、mask 等参数按后端实际能力出现；不展示所有后端都能精准控制强度或固定 seed 的假象。

## 5. 精度约束

基准 B 是方向、尺寸、色彩已明确处理的不可变版本。有效 alpha 的非零范围只能落在 E−K。模型可观察更大的 C，但 C 不是修改授权。

- 羽化向内进行，或先明确更新允许编辑范围；最后恢复保护区像素。
- 用与 B 同尺寸、同色彩处理的 PNG 像素数组检查：`protected_changed_pixels = 0`、`outside_edit_changed_pixels = 0`。
- 零差分只说明范围约束；保护 mask 覆盖是否正确、身份和美观仍需检查。
- JPEG 重编码、整体调色或整图超分作为单独派生操作；不能继续承诺与 B 零差分。
- 下颌、脸颈、发际、衣领、手臂遮挡与新旧衣物边界是必查部位。效果不自然时不能仅靠扩大羽化解决。
- 选区很小仍允许修复；不使用“至少占整图 1%”的门槛。
- 生成图发生主体移动、比例变化或无法对齐时，不直接拉伸拼回并宣布成功。

## 6. JSON 协议与图像资产

常规 Agent 交接为一段 JSON，包含格式版本、图片引用/哈希/尺寸、基准/revision、原图坐标区域、保护、意图与顺序。照片作为独立文件/资产，PNG mask 在执行时由 JSON geometry 生成；不要求用户搬运 ZIP。

图片字节不默认嵌入 base64。跨客户端连接同一工作区可直接解析资产；跨设备需先让对方取得图片并显式绑定，不能认为一段引用即可复制照片。导入校验图片与版本，不自动读取任意路径、不执行脚本、不启动生成。

现有标注协议与下一阶段“建议草稿 → 用户修改 → 确认 → 执行”状态机见 [agent-workflow.md](agent-workflow.md)。建议草稿必须与正式人工标注分离，服务端记录确认，编辑后旧确认失效。

首版工作基准为明确的 sRGB 图像；保留原文件与方向/尺寸信息，Agent 区域基于归一化后的照片，而非屏幕截图坐标。

## 7. 隐私与自主权限

“本地”指明确的个人设备处理边界，可包含 Mac 控制端到 Windows GPU 的私网传输。ComfyUI 中的 API 节点可能访问远端，Agent 视觉模型也可能在远端；两者分别配置。

建议默认私人照片使用本地生成；远端分析与 GPT 生成需在项目/任务内明确允许。裁切图与缩略图同样算图像外传。授权过的任务正常执行不反复询问，越出目的地、范围、对象或预算才请求介入。

严格本地模式必须配有已验证的本地观察/分割能力，或由人工提供完整标注；否则显示“需要人工标注”，不擅自上传图片。编码器或 MediaPipe 节点存在不等于通用本地视觉 Agent 已可用。

## 8. 首版之外

RAW 显影、完整 16-bit/印刷色彩、任意 Photoshop 图层兼容、多用户实时协作、云账号体系、视频编辑、插件市场和复杂批量模板均不进入首版。原生安装包可在工作流成立后增加。

## 9. 验收矩阵

以下是待实现后的验收条件，尚未执行。

| 场景 | 证据 |
|---|---|
| 人工精修 | 导入合成照片，画 3 个区域，重开恢复，生成候选并接受 |
| 协同精修 | Agent 提议区域，人修正，执行冻结快照；结果和意图可追踪 |
| 自主精修 | 无人工开画布完成一个范围清楚的任务；有限重试；不能完成时明确交人 |
| 精确保护 | 独立制作保护 mask；PNG 全域差分为零；原尺寸检查覆盖范围 |
| 跨 Agent | 三个目标客户端分别跑同一组 MCP 操作；图像观察能力单独记录 |
| 跨设备 | Mac 项目到 Windows 执行，下载产物后位置/尺寸/坐标一致 |
| JSON 交接 | 同机跨客户端读取/修改 JSON；哈希/版本不匹配明确失败；跨设备取得图片并绑定后再执行 |
| 异常恢复 | 网络失联、显存不足、版本过期、服务恢复均不丢输入或重复提交 |
| 隐私 | 未允许的远端无法读取图像资源；日志/包内无凭据 |
| 质量 | 下颌、发丝、衣领、旧衣残留、旁人保护等代表性样例原尺寸验收 |

耗时、成功率和大图性能先记录真实基线，性能目标由实测确定，不沿用旧稿未经验证的秒数。
